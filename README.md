# GrievanceAI — User + Developer Portals

A Flask web app with public user sign-up/login and a separate, environment-provisioned developer console. Uses SQLAlchemy and supports SQLite locally or PostgreSQL on Render.

## Features
- User sign-up and login with hashed passwords; logout.
- Users can create grievances and see only their own records.
- Developer console lists all grievances and registered users, exposes complaint details, provides search/status filters, and lets the developer update status and priority.
- Keyword-based category/priority suggestions (not a trained AI model).
- Developer role is never available through public registration.

## Run locally

```bash
python -m venv .venv
# Windows PowerShell: .venv\Scripts\Activate.ps1
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
```

Set environment variables before running:

```bash
# Windows PowerShell examples
$env:SECRET_KEY = "replace-with-a-long-random-secret"
$env:DEVELOPER_EMAIL = "developer@example.com"
$env:DEVELOPER_PASSWORD = "replace-with-a-strong-password"
$env:DEVELOPER_NAME = "GrievanceAI Developer"
python app.py
```

On macOS/Linux, use `export KEY=value` instead of `$env:KEY = ...`. Open http://127.0.0.1:5000. SQLite is created automatically for local development.

## Deploy to Render
1. Create a new GitHub repository and upload all files, keeping `templates/` and `static/` folders.
2. In Render, choose **New + → Blueprint** and select that repository (or create a Python web service and attach PostgreSQL manually).
3. The included `render.yaml` configures a web service and PostgreSQL database.
4. Set `DEVELOPER_EMAIL` and `DEVELOPER_PASSWORD` as Render environment variables. Use a long, unique password. Set a strong `SECRET_KEY` if not already generated by the Blueprint.
5. Deploy. The developer logs in through `/login` with the provisioned email/password; public `/signup` only creates ordinary user accounts.

If the developer email already exists as a normal user, the app deliberately does not silently promote it. Use a fresh developer email or update the role manually in a controlled database migration.

## Important security notes
- Do not commit secrets or real user data to GitHub.
- Developer access is role-checked server-side, not just hidden in the interface.
- This starter app does not yet include email verification, password reset, audit logs, rate limiting, CSRF protection, or formal data-retention controls. Add these before production use with sensitive grievance data.
- Classification is a keyword heuristic; do not treat it as a reliable AI decision or use it to automatically deny or deprioritize a complaint.
